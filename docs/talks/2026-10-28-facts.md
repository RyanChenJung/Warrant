# Facts for the October 28 talk

One page every section of the talk uses, so the words and numbers match. Every number has its
source in this repo. Plain words go on the slides; the technical terms stay in the methods and in
`CONTEXT.md`, whose last section lists the same plain names.

## The question, in one sentence

Before a data AI has any users, it gives wrong numbers, without warning, wherever the data itself
cannot show what it means. We run automatic checks on the data first, and ask the person who knows
the business only about what the checks cannot settle.

Title: *Which questions should a data AI ask an expert on day one?*

## Plain words

| On the slides | Technical term (`CONTEXT.md`) | Note |
|---|---|---|
| note | claim | something the AI writes down about the data and reuses |
| the AI's notes | knowledge store | not "memory" |
| automatic data checks | check battery | the vendored Gloss detectors; no AI involved |
| the checks settle it | settled | relative to these checks; not "prove" |
| possible explanation | reading | e.g. "the orders were cancelled" against "they belong to another system" |
| checks-first | settlement rule | the agent writes what the checks settle; the rest goes to the expert |
| confidence-first | confidence rule | the expert gets the same number of questions, the AI's least confident ones |
| planted problem | injected defect | changed by us after the freeze, so we know the truth |
| expert | person | in the experiment, simulated by the reference claim |
| questions to the expert | questions to a person | the matched number both rules get |
| wrong number, no warning | silent error | not "confident error" |
| day one, cold start | (none) | before any use has built up |

## The data and the three planted problems

- Data: LiveSQLBench-Base-Lite, SQLite release, revision `0664a2f` (`configs/livesqlbench-base-lite.yaml`); two of its databases, a crypto exchange and an alien-signal observatory set.
- We planted one problem of each kind (`freeze/write_line.yaml`):

| Problem | What we changed | Do the checks settle it? |
|---|---|---|
| Wallet formula | `walletsum` now also includes the margin balance (1,000 rows) | **Yes**: the checks find the new formula |
| Cancelled orders cut | 266 cancelled orders removed from `orders` (999 → 733); their fills, fees and risk records kept | **No**: the checks see 266 records with no order, not why |
| Seeing codes | Excellent / Good / Poor recoded to 1 / 2 / 3 (315 / 357 / 291 observatories) | **No**: nothing in the data says whether 1 is best or worst |

- So checks-first sends **2 questions** to the expert (the second and third); confidence-first gets the same 2 (`freeze/write_line.yaml`, `matched_asks`; computed from the committed predictions).
- A question the checks themselves wrote (run on the injected copy, 2026-10-20): "266 ordersmark values are missing from orders. What are they?" with the options *retired or historical records*, *records from a system not present here*, *data-entry errors*, *unsure*, about 25 seconds. The true answer, cancelled orders cut from the table, is not among them.

## What is already done

- **Freeze**, every setting public before anything was planted: commit `6676db7`, PR #105, 2026-10-19 03:34 UTC.
- **Problems planted** after the freeze: `injections/9cfd501f2182-write_line.json`, PR #110, outcome `built`.
- **Predictions**, committed before any AI answer (`predictions/9cfd501f2182-write_line.json`, PR #111): wallet formula *the AI alone*; cancelled orders *both the AI and the expert*; seeing codes *the expert only*.
- **Pilot** (2026-10-20, `results/pilot/`, PR #115): the cancelled-orders problem, 8 questions, Claude Sonnet 5, one run each.
  - No notes: **3 of 8** right. With the expert's note: **7 of 8**.
  - The 4 questions about cancelled orders: **0 of 4 → 4 of 4**.
  - "How many orders were cancelled?" without the note: **756** (it counted fills with a cancel reason); the true number is **266**. No refusal, no warning.
  - About 15,900 input and 870 output tokens per answer.
  - One run per question: a first look, not a result.

## What is not done yet

- The comparison itself, checks-first against confidence-first at the same 2 questions: the full run (#54).
  - **Questions:** 33 (#52). 9 are on the cancelled orders, 6 on the wallet formula and 8 on the seeing codes, plus 10 controls.
  - **Notes:** 5 ways of filling them. The AI writes its own notes under two instructions (ADR 0012). One writes every note with its confidence, and that is the one the test uses. The other is told not to guess and is reported alongside. So there are 8 sets of notes in all.
  - **Schedule:** the first complete pass, one run each (264 answers), is planned by **November 16**. Runs 2 and 3 follow, 792 answers in all.
  - **Cost:** estimated at about $40 to $45, with a hard cap of $100 (#54).
  - **The test:** a one-sided exact sign-flip test at 0.05, fixed in the freeze.
- A real expert: in the experiment the expert is simulated and always right.
- Notes that go stale when the business changes a definition: paused (ADR 0010), future work.

## What we may not say

- Not "the AI was confident": the pilot did not record its confidence. Say "with no warning".
- Not "the fewest questions": we compare which questions, at the same number. Say "with the same number of questions".
- Not "proven" for what the checks settle: it is relative to these checks.
- Not that confidence-first fails: that is what the full run tests.
