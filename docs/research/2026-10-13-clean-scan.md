Generated by `uv run python -m warrant.data.clean_scan --today 2026-10-12 --defect-subjects column_formula:crypto.accountbalances.walletsum coverage:crypto.orders value_meaning:alien.observatories.seeingprofile` from the pinned release (`birdsql/livesqlbench-base-lite-sqlite` at revision `0664a2f28555faa0dd2947c8c23288df79bcc06b`): the eight checks of Gloss's `run_all` (the seven vendored detectors and the ordinal-direction probe), called directly in its order on a CSV export of each clean copy, with DuckDB 1.5.5 and the detectors' date fixed to 2026-10-12. No model is called and no documentation is passed to the detectors. Every finding, with its statement and evidence, is in [clean-scan.json](clean-scan.json), which is identical between two runs with the same date. Table and column names and values quoted here come from LiveSQLBench-Base-Lite (CC BY-SA 4.0).

## How the scan reads the data

- **Peers.** A table's peers are the tables linked to it by a declared foreign key, in either direction. The link detector also gets the declared keys and pairs them from child to parent only (#28).
- **Export.** Table and column names are kept as declared; floats are written in positional notation.
- **Empty strings.** NULL and the empty string are both exported as an empty cell, and the detectors read both as NULL. The summary counts the cells this merges per database.

## Mapping from assertion type to claim kind

A finding is listed under every claim kind of its assertion type.

| Assertion type | Claim kind | What the detector reports |
|---|---|---|
| SCOPE | coverage | which population the table covers: its date window, or a column dominated by one value |
| GRAIN | grain | what one row is: the unique key, a top-level and child split, columns that map one-to-one |
| FIELD | value meaning | what a column's values are: with no documentation passed, non-breaking spaces, and the direction of an ordinal scale from the ordinal-direction probe |
| VALUE | value meaning | what stored values stand for: code lists, value formats, variant spellings |
| LINK | coverage and grain | unmatched and never-referenced key values (what is omitted) and the cardinality of a join (what a row counts as after it) |
| RULE | column formula | an arithmetic relation between columns found by the identity search |
| LIMIT | coverage | what is absent: empty and sparse columns |

**No assertion type maps to term boundary.** No detector reports on what a business term includes, so the scan can list no finding of that kind. LINK is the only type that maps to two kinds.

## Caveat: tables the GRAIN detector splits on a column that is not a declared key

The GRAIN detector splits a table into top-level and child rows when it reads a column as pointing back at the table's own unique key: at least 95 percent of the column's populated values are among the key's values, and some rows leave the column empty. Every other detector then measures the top-level rows only. 3 of the 175 tables are split, and in 3 of them no declared foreign key from that column to the table supports the split:

- museum.`airqualityreadings`: split on `ozoneppb`, keeping 18 of 951 rows
- museum.`conservationandmaintenance`: split on `prevtreatments`, keeping 87 of 951 rows
- museum.`surfaceandphysicalreadings`: split on `microbialcountcfu`, keeping 3 of 951 rows

On these tables the column is populated with numbers that also occur as key values, and the rows the split keeps are those where it is empty. The SCOPE, VALUE, RULE and LIMIT findings there, including the identity relations marked below, describe only the rows kept, and the week-one check (#59), which applies no grain filter, does not report those relations.

## Reach of the ordinal-direction probe

The probe needs two date columns in the same table, and a column with 3 to 50 distinct numeric values among the rows the GRAIN split keeps. 11 of the 175 tables have two or more date columns, and 6 of those also have such a column: credit.`core_record` (depcount, addrstab, phonestab, emailstab, tenureyrs); fake.`moderationaction` (susphist, appealnum); insider.`compliancecase` (prevviol, fposrate); vaccine.`container` (coolrefills); vaccine.`regulatoryandmaintenance` (incidents); vaccine.`vaccinedetails` (dosepervial). The probe reports 0 findings, so it reports on none of them.
